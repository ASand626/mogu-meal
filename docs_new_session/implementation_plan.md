# 新セッション引き継ぎ用：実装計画（Implementation Plan）

ログイン処理の改善、ログアウト時のデータ保持不具合の修正、ゲストモード機能の追加、および第2段階（ローディングUX改善、誤作動防止メニューの追加）の計画です。

---

## 🔍 特定した課題と原因分析

### 1. ログイン時に待たされる原因
* **原因**:
  * 以前の `login` 関数内で、新規ユーザーだった場合にGoogleアカウントを強制削除（`delete()`）する重い非同期処理が行われており、これがFirebase Authのログイン監視リスナーと激しく競合ループを起こしていたため、長い待機時間が発生していました。
* **解決策 (第1段階で実施済み)**:
  * Googleログインボタンを1つに統合し、新規・既存に関わらずスムーズにログインさせます。新規ユーザーの場合はデータがFirestoreにないため、そのまま初期設定画面へ案内する設計にし、アカウント削除に伴う競合を完全に排除しました。

### 2. ログアウト後に再ログインすると設定が初期化される原因
* **原因**:
  * 設定画面（`/settings`）で、Firestoreからのデータロード完了時にフォームの値を同期する処理がなかったため、ロード前のデフォルト値（大人2、子供1）でFirestoreが意図せず上書き保存されてしまっていました。
* **解決策 (第1段階で実施済み)**:
  * 設定画面にデータ同期（`useEffect`）を追加し、ロード完了時に正しい設定値が画面に自動反映され、デフォルト値での上書きを防ぐようにしました。また、ログアウト時にローカルキャッシュ（`localStorage`）も完全にクリアし、不整合を防ぎます。

### 3. 手動ログイン時に「読み込み中」が長く感じられる問題 (新規追加課題)
* **原因**:
  * `onAuthStateChanged` リスナーの先頭で毎回 `setLoadingAuth(true)` を呼び出しているため、手動ログイン時にも画面全体が「読み込み中...」の白いスクリーンで覆われ、Firestoreの取得が終わるまでロックされてしまいます。
* **解決策 (第2段階で実装予定)**:
  * `onAuthStateChanged` リスナー内での `setLoadingAuth(true)` の強制呼び出しを廃止します。
  * `loadingAuth` はアプリの初期起動時（オートログイン確認）のみ `true` になるようにし、手動ログイン時は画面全体をブロックしません。ログイン成功と同時にアプリのメイン画面がアクティブになり、裏でFirestoreのデータがロードされてスーッと画面に反映される滑らかな体験（UX）に改善します。

### 4. ユーザーアイコンタップで勝手にログアウトしてしまう問題 (新規追加課題)
* **原因**:
  * スマホ画面などの狭いレイアウトでは、ログアウトボタンが「ユーザーアイコンのみ」に縮小されるため、アカウント確認などのつもりでアイコンを誤タップした際に、確認なしで直接 `logout()` が実行されてしまう問題がありました。
* **解決策 (第2段階で実装予定)**:
  * アイコンをタップした際に勝手にログアウトするのをやめ、その場に美しい**「アカウント確認 ＆ ログアウト用ドロップダウンメニュー」**を展開する仕様に変更します。
  * ドロップダウンメニュー内には、現在ログイン中の Google アカウント名、メールアドレス、および明確な「ログアウト」ボタンを表示します。これにより、誤タップでのログアウト事故を100%防ぎます。
